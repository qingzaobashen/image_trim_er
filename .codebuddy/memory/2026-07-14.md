## #19 首页抠图画布区域实现图片拖入功能

用户需求：在首页抠图（cutout）的画布区域支持把图片文件直接拖入加载。

改动（4 处）：
- `index.html`：给 `.canvas-area` 加 `id="canvasArea"`；在 `canvasWrapper` 内新增 `.drop-overlay` 提示层（`data-i18n="canvas.dropHere"`）。
- `src/js/main.js`：新增元素引用 `canvasArea`/`dropOverlay` 与 `_dragDepth` 计数器；在 `initEventListeners` 绑定 `dragenter`/`dragover`/`dragleave`/`drop` 到 `canvasArea`；新增 `handleDragEnter`、`handleDragOver`、`handleDragLeave`、`handleDrop`、`getImageFileFromDataTransfer`、`setDragOver` 方法。拖入图片走既有的 `loadImageFile`（loadImage 内部会重置 currentMask/shadowMask 并 `undoRedoManager.clear()`，替换旧图无残留）。
- `src/js/i18n/locales/zh-CN.js` 与 `en-US.js`：canvas 段新增 `dropHere` 键。
- `src/css/style.css`：新增 `.drop-overlay`（默认隐藏、虚线边框+半透明遮罩）与 `.canvas-area.drag-over .drop-overlay`（显示）样式。

### 验证（Chrome DevTools 真实页面）
- 合成 DragEvent + DataTransfer(图片 File) 拖入：dragenter/over 显示高亮、dragleave/drop 清除；drop 后 uploadPrompt 隐藏、mainCanvas 可见、尺寸与 infoPanel 正确更新（40×30 加载成功）。
- 非图片文件拖入：高亮显示但不加载（`imageSize` 仍为 `-`），弹警告提示。

注意：`node --check` 通过；lint 0 错误。Vite dev server 已后台启动于 http://localhost:5173/。

## #20 图片裁剪页画布区域扩大并改为 1:1

用户需求：图片裁剪页（pages/crop.html）的画布区域扩大，且长宽比例改为 1:1。

改动（仅 CSS，页面专用 <style> 内 `.crop-canvas-container`）：
- 移除 `min-height: 400px`；改为 `max-width: 760px` + `aspect-ratio: 1 / 1` + 居中（`margin: 0 auto 20px`）。容器变 760×760 正方形，画布像素在 `crop.js` 的 `_fitCanvas()` 中按 `container.clientWidth/clientHeight` 动态取值，自动跟随为正方形。
- 移动端 `@media (max-width:768px)` 段将 `.crop-canvas-container { min-height: 280px }` 改为 `max-width: none`，让 1:1 按屏幕宽度铺满。

说明：本次只改「画布预览区域」为正方形，默认裁剪选区仍按原图比例（未强制 1:1）。若用户后续要求默认裁剪框也固定 1:1，需在 `_loadImageFromDataUrl`/`_resetCrop` 中按较短边生成正方形 cropRegion。

### 验证（Chrome DevTools 真实页面）
- 未加载图时强制显示工作区：容器 clientWidth=clientHeight=758，aspectRatio="1 / 1"。
- 加载 1200×600 宽图：cropCanvas 像素 758×758（ratio 1.000），原图信息正确，默认裁剪选区 960×480（保留原图比例）。

## #21 裁剪页默认裁剪选区占满整图

用户需求：图片裁剪页默认裁剪选区一开始就要占满整个图片（不要再留 10% 边距）。

- 加载 900×450 图：默认 cropSize="900 × 450 px" == 原图；点「重置」后仍为 "900 × 450 px"。node --check 通过，lint 0 错误。
